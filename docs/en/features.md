# Features

[한국어](../ko/features.md)

This page describes what choco-pi adds to Pi, grouped by area. [Common commands](commands.md) lists the main slash commands in one table.

## Operating rules and workflows

- [`profile/SYSTEM.md`](../../profile/SYSTEM.md) sets shared rules for scope, authority, evidence, and completion. [`profile/model-guidance.md`](../../profile/model-guidance.md) adds guidance for each model, and [`profile/writing-policy.md`](../../profile/writing-policy.md) sets the rules for response prose.
- The agent loads the root `AGENTS.md` and, as it works in subdirectories, the path-scoped `AGENTS.md` files it finds there.
- Workflow skills cover direct implementation (`task-inline`), parallel units (`task`), dynamically decomposed work (`task-dynamic`), urgent fixes (`task-hotfix`), adversarial review (`review`), reproducing review claims (`verify`), TLA+ model checking (`formal-verify`), environment readiness (`check`), signed local commits (`commit`), and prose (`effective-writing`). Implementation workflows hold a mutation lease on the checkout, validate against acceptance criteria, and never push. [Review and verification](#review-and-verification) describes the review and evidence skills.
- `/preferences` sets the response language, the response style, and the agent persona. The style is `balanced` (the default), which keeps final answers short and gives a few sentences of status during long work; `concise`, which keeps every update to one line; or `explanatory`. The persona, `unset`, `critical`, or `pessimistic` (the default), controls how strictly the agent tests its own claims and plans.
- `/preferences` → Agent → On usage limit (`agentOnUsageLimit`) decides what happens when the active provider reports that a usage quota has run out:
  - `none` (default): the run ends with the error.
  - `fallback`: the run switches to a model of a similar tier on another provider, chosen from [`profile/model-fallbacks.json`](../../profile/model-fallbacks.json), and continues. When no candidate of that tier is available, it falls back to the last-resort models in this order: `xai/grok-4.7`, then `synthetic/hf:moonshotai/Kimi-K3.1-Pro` (preferred over Kimi K3), then `synthetic/hf:moonshotai/Kimi-K3`.
  - `auto-resume`: the run waits for the quota to reset, then continues.

  Subagents report a limit to their parent with the reset estimate and a suggested in-scope model; under `auto-resume`, they are parked and resumed after the reset. While a `/goal` is active or paused, the goal runtime handles the recovery instead.

  A limit that covers only some of a provider's models closes only those models. Anthropic's Fable weekly limit covers the Claude Fable and Claude Mythos series, so Opus, Sonnet, and Haiku keep running while it is exhausted. Live usage data decides which limit a failure hit. For a Fable limit, `fallback` tries `openai-codex/gpt-6-astra` first, then Opus on Anthropic, and only then the last-resort models. A scoped limit choco-pi does not recognize closes only the model whose request failed.

## Agents and orchestration

- Specialist roles in [`profile/agents`](../../profile/agents) (`advisor`, `explore`, `general`, `handoff`, `implementer`, `planner`, `reviewer`, `verifier`) run as background subagents, as scheduled runs, in isolated Git worktrees, or as dependency-ordered workflows through `workflow_run`. `/agents` manages them.
- `max_turns` also limits resumed runs, and an agent with a token budget is told to conclude before the budget stops it.
- A fleet panel shows running subagents and managed background shells together. Clicking a row selects it, as the arrow keys do, and double-clicking a shell opens its output. Selecting a subagent focuses its transcript, which streams text, tool progress, and custom messages; the thinking toggle there affects only the focused view. Shells belong to the session that started them and are managed with `shell_start` and `/shells`. When a shell finishes while its owning session is inactive, the completion is delivered once that session becomes active again.
- `/btw` opens a parallel, read-only side conversation on the main session's model and thinking level. It runs as the internal `side-chat` agent, named `side-chat`, `side-chat-2`, and so on; other callers cannot spawn that role.
- The blocking `advisor` tool gives root or child agents a fresh, read-only second opinion from a stronger model that you configure, based on a bounded excerpt of the live session. It is off by default, and it skips the consult when the advisor model is the same as the session model. Configure it in `/preferences` under Agent → Advisor Agent, or in [`advisor.json`](configuration.md#advisor-settings).

## Review and verification

- `/review [target]` has an agent review the changes adversarially. The `review` skill freezes the target (by default, staged and unstaged changes against `HEAD`) into an immutable bundle and hands it to one fresh, read-only `reviewer`. [`profile/review-policy.md`](../../profile/review-policy.md) makes every review cover three angles: changed behavior that callers, tests, or documentation still rely on; the callers of every changed contract; and a final pass for anything the earlier passes missed. The reviewer reports findings and, separately, candidates: concerns whose traced path to a violation has a missing or assumed link. A violation traced completely is a finding even when the reviewer ran nothing. Both stay advisory until the agent or a verifier checks them.
- Reviewers and verifiers end their reply with a structured block (`choco-pi-review` or `choco-pi-verdict`). When one runs under a work task, the subagents package records the block and adds a `Verdict record:` line to the result. A review whose block is missing or invalid is not recorded and is never reported as clean. Review and verification rounds are capped per work task; `/review-continue <work_task>` and `/verify-continue <work_task>` allow more.
- In the terminal, a block that parses is shown as a short summary (the verdict, counts, and one line per finding or claim) in the result card, the completion notification, and the transcript Markdown; expand the card to see the raw block. A block that does not parse is shown unchanged, after one line giving the parser's reason. Only the display changes: the stored message, what the model receives, and the recorded verdict stay as they were.
- The `verifier` role follows the `verify` skill: it tries to reproduce a reviewer's claim against an exact checkout snapshot. It writes only to scratch space, never fixes code, and reports an `UNPROVEN` result as it stands; a failed reproduction does not refute a claim. Small changes get no verifier.
- The `formal-verify` skill checks ordering and state promises in the projects the agent works on, such as a run that must settle exactly once or a lease that must never be held twice. The agent writes a small TLA+ model, checks it with TLC through the skill's wrapper, and shows that each rule fails when the model is deliberately broken. A pass applies to the model within its bounds, not to the code. A drift check reports when code that a model covers has changed. Models can describe code in any language, but the drift check hashes individual symbols only in TypeScript and JavaScript, and hashes other files whole. TLC needs Java 11 or newer and a one-time `tlc-setup.ts` run, which downloads the pinned `tla2tools.jar` into `${XDG_CACHE_HOME:-~/.cache}/choco-pi/formal`. See the [skill](../../profile/skills/formal-verify/SKILL.md); [`formal/tla/subagent-run`](../../formal/tla/subagent-run) is a worked example that models this repository's subagent run lifecycle.
- `/diff` docks a pane beside the transcript that lists the changed files with their diffs and refreshes as the agent works.
  - **What it compares.** By default, the pane shows the changes made since the session began: the working tree against the session's first file checkpoint, including changes committed since then. `/diff source uncommitted` compares `HEAD` with the working tree, `/diff source turn [<n>]` compares the working tree with a turn's checkpoint, and `/diff source branch [<base>]` compares from the merge base with a branch (by default the remote's default branch, else `main`, else `master`). A chosen source stays in effect until the pane closes; `/diff source session` returns to the default. Completion after `/diff` lists the subcommands.
  - **Sending to the editor.** From the pane, you can put a reference to a file, a hunk, or selected lines into the editor. You can keep notes on hunks with `c` and ask about all of them at once with `a`, which puts them into the editor as one message and clears them from the pane; with no notes, `a` puts the cursor's file, hunk, or lines there. You can also step through findings recorded by reviewers and verifiers, and put a `/review` instruction into the editor (`/diff review`). Nothing is sent until you press Enter.
  - **Sensitive files** are listed by name, and their contents stay hidden until you press `v` on one. Nothing is saved: the file is hidden again when the pane reopens.
  - **Moving around.** Ctrl+Alt+P toggles the pane, Ctrl+Alt+F moves focus into and out of it, and `?` inside it lists its keys. Inside the pane, `j`/`k` step through files, and ↑/↓ step through the lines of open files. Shift+↑/↓ or a mouse drag selects a range of lines, a click puts the cursor on a line or hunk, and a click on a file's row expands or collapses it.
  - **Copying.** Cmd+C on macOS (Ctrl+C elsewhere) copies the selected lines as plain code, or the whole hunk as a diff when the cursor is on its header. This works only if the terminal passes Cmd+C on to Pi. Pi's own mouse select-and-copy is off inside the pane and on the review's diff, where the mouse selects diff lines.
  - **One turn at a time.** ← and → show one turn's changes on their own: ← steps back from the newest turn, and → steps forward and, after the newest turn, returns to all of the session's changes. A turn's changes run from its file checkpoint to the next one (to the working tree for the newest turn). Edits you make between two prompts therefore count toward the earlier turn, and a prompt that started from unchanged files is shown together with the turn before it.
  - **Focus and the editor.** Shift+→ moves focus from the editor into the open pane when the cursor is at the end of the text and nothing is selected; elsewhere, it extends the editor's selection. Tab, Esc, `q`, Shift+←, a click beside the pane, or a click in the prompt editor gives focus back, and a click in the editor's text also puts the cursor on the clicked character. Dragging over the editor's text, or holding Shift with the arrow keys, selects that text. Backspace or Delete removes the selection, typing or pasting replaces it, Ctrl+C or Ctrl+X copies it and keeps it selected (Cmd+C too, where the terminal passes it on to Pi; with nothing selected, these keys keep their usual meaning), and Escape drops it.
  - **Narrow terminals and Zed.** The pane needs the fullscreen TUI and a terminal at least 65 columns wide; otherwise, `/diff` prints the list of changes. In Zed, it sends bounded native diffs instead, each preceded by its file name and status, and lists sensitive files by name only. When the session has changed nothing yet but the working tree has changes, it says that `/diff source uncommitted` shows them ([details](../zed-command-parity.md#diff-in-zed)).
- `/review-assist [target]` is where you review changes yourself, without adding anything to the model's context.
  - **Targets.** You can review the current session or one of its turns, a branch range, uncommitted changes, a saved review, or a GitHub pull request. You can comment, approve or reject, and submit the review to the pull request. `session` lists the same files as `/diff`, from the session's first checkpoint, and `session turn <n>` counts checkpointed turns from 1.
  - **Keys.** The view is the `/diff` pane's view at full screen. It uses the pane's keys for what both views do: `n`/`N` or `[`/`]` for hunks, Enter or Space to fold, `g`/`G`, `r`, `f`/`F`, `v`, and `?`. It adds a line cursor, moved with `j`/`k` or ↑/↓, for the review's own work. Shift+↑/↓ or a mouse drag selects lines; a click puts the cursor on a line or opens and closes a file; Cmd+C (Ctrl+C outside macOS) copies the selected lines as plain code (a folded hunk as a diff); `c` comments; `m` marks a hunk as reviewed; `a` opens a side chat; `/` searches changed lines (`>`/`<` for the next match); `+`/`-` show more or less context; `|` switches to a split view; `e`/`E` open the editor; `S` finishes; and `q` or Esc saves and leaves.
  - **Keeping up with changes.** When the changes end at the working tree, `r` reads them again, and so does each finished side-chat tool call. `f`/`F` step through findings recorded by reviewers. Reviewed marks and comments stay on hunks whose content is unchanged, and comments whose code has changed since are shown as outdated.
  - **Sensitive files**, such as `.env`, private keys, and paths containing `secret` or `credential`, are listed with their contents hidden until you press `v` on the file, for this view only.
  - **Hidden files and the side chat.** The side chat is told which files are hidden. Until you press `v` on a hidden file, any side-chat tool call with an argument that names that file is refused. The name is matched in two ways:
    - As a path, resolved the way Pi's file tools resolve it and more broadly: surrounding spaces, `@`, `~`, `file://`, `..`, trailing slashes, symbolic and hard links, Unicode forms, and letter case where the file system ignores it.
    - Anywhere in the argument's text, as the path or the base name, including when it is quoted or escaped for a POSIX shell, fish, PowerShell, or cmd, or percent-encoded (`cat .e"n"v`, `cat o\'key.txt`, `type .e^nv`). This also refuses a different file whose name differs from a hidden one only by quote or escape characters.

    Text that `write` and `edit` put into a file is checked as a path only.

  - **Limits of this check.** It is a second line of defense, not a sandbox. A name is refused when every character of it appears in the text as itself or percent-encoded. It does not stop a command that writes a character by its code or reaches the file without naming it: a glob such as `cat .e*` or `cat *`, brace expansion, a variable, an escape such as `$'\x2e'`, a recursive search, an environment dump, or a script written earlier. Nor does it stop anything the chat has already read.
  - **Messages.** Messages, warnings, and errors appear on the review's own message line. Errors also stay in Pi's notifications, so you can read them after the review closes.
  - **Untrusted text and large changes.** File names, diffs, and other untrusted text are stripped of terminal control sequences before display. Large changes are read within limits, and the view says how many files it left out.
  - **Saved reviews** live in `choco-pi/reviews` under Pi's agent directory. They are deleted seven days after their file was last modified, including reviews with unsent comments.
  - **Outside the terminal UI**, `/review-assist` prints a read-only summary. In Zed, the summary is Markdown, with each file's changes as a unified diff in a code block.

## Sessions, context, and goals

- You can list, create, read, steer, and wait on project conversations from another session (`/sessions`, `/session-new`, `/session-read`, `/session-send`, `/session-wait`).
- `/goal` keeps a persistent objective across turns and compaction.
- `/checkpoint` rewinds, rolls back files, or forks at a checkpointed turn, or forks the current state. `/rewind` only rewinds the conversation; `/fork` only forks, from an earlier turn or the current state.
- Context limits are two presets in `/preferences`: **Context soft cap** under Session → Context, and **Auto-compaction point** under Session → Compaction.
  - The soft cap limits usable context: strictest 250K, strict 400K, standard 600K, permissive 800K, or unlimited. It defaults to permissive.
  - The compaction point sets where compaction starts: strictest 200K, strict 300K, standard 450K, permissive 600K, or unlimited. It defaults to standard.

  Each preset is fitted to the model's native window. The cap never exceeds that window, and the compaction point stays below the cap by a headroom of `min(100K, 15% of the cap)`, but never less than the host reserve plus 8K. For a model whose native window is under 64K, Pi's own compaction trigger applies. When OpenAI publishes a native-compaction budget for a model, that budget also limits the compaction point. These two presets are the only settings; the headroom is fixed.

- Compaction modes are set in `/preferences` under Session → Compaction:
  - **OpenAI compaction** uses OpenAI's remote compaction for the Codex transport and configured Responses providers. This profile's [`profile/choco-pi-codex.json`](../../profile/choco-pi-codex.json) sets it to server-side.
  - **Anthropic compaction** defaults to server-side. It uses Anthropic's on-demand compaction only with OAuth on `api.anthropic.com`, for Fable 5+, Mythos 5+ and Preview, Opus 4.6+, Sonnet 4.6+, and Haiku 5.5+.
  - **xAI compaction** defaults to server-side and uses xAI's `/responses/compact` for `grok-*` models on `api.x.ai`, with OAuth or an API key. It covers foreground compaction only.

  If server-side compaction fails, choco-pi falls back to its local summary, which is reconciled with the retained messages. Background compaction is on by default. When it is on, it always runs the text lane, and runs each native lane (OpenAI and Anthropic) only while that vendor's row is set to server-side.

- The startup header shows the choco-pi logo, the choco-pi and Pi versions, and the key hints. Pi's model scope and its list of loaded resources are hidden unless you start with `--verbose`, but load problems such as skill collisions still show. `quietStartup: true` hides the header too.
- New sessions are named automatically. `sessionAutoNameModel` selects the naming model (default `openai/gpt-6-luna`); set `sessionAutoName` to `false` to turn naming off.
- After each completed agent turn, choco-pi predicts your next prompt with `openai/gpt-6-luna` (falling back to `anthropic/claude-haiku-5-5`) and shows it as dim text in the empty editor. Tab fills it in; nothing is sent until you press Enter. Suggestions are conservative. One appears only when the agent's last reply needs your input, and never while something will resume the agent on its own: a queued message, a running subagent or background shell, or an active `/goal`. A suggestion in a writing system that neither your own prompts nor `agentLanguage` use is dropped. Each turn sends recent conversation text to the suggestion model in one small request; set `promptSuggestion` to `false` to turn suggestions off.

## Code intelligence and Code Mode

- choco-pi-lsp provides LSP navigation and diagnostics, lint integration, ast-grep and tree-sitter search and rules, and semantic tools such as `symbol_search`, `module_report`, and `read_symbol`. `/lsp on|off|status` and the `/lens-*` commands control it at runtime.
- Code Mode's `exec` tool runs restricted JavaScript that composes several tool calls in one step; its notebook mode keeps persistent Deno TypeScript state. choco-pi-codex also provides Codex-style tools, such as `apply_patch` and `exec_command`, and Responses compaction. `/codex` opens its settings.
- Most tools are deferred: they load only when `tool_search` finds them, which keeps the always-loaded tool list small. choco-pi's `tool_search` also finds choco-pi's own tools. In Code Mode, it lists the tools callable as `tools.<name>` inside `exec` without changing the loaded tools; elsewhere, it loads the matches for the next call. Pi's built-in `grep` tool is disabled; the agent finds source code through `symbol_search`, `module_report`, targeted symbol reads, navigation, and AST search.

## Research and integrations

- Web research uses one deferred `web_search` tool, whatever the conversation model. Search credentials and billing come from the selected search backend (OpenAI, Exa, Kagi, Synthetic, Brave, or xAI), not from the conversation provider. The xAI (Grok) backend runs only when a request or the routing configuration names `xai`, and only while xAI is signed in; each call is billed. [Web search](web-search.md) covers providers, routing, privacy, and fallback behavior.
- `fetch_content` extracts page content, and `source_check` verifies claims against cited passages. `/search` browses stored results; `/websearch` and `/curator` drive the search curator workflow.
- Pi's built-in MCP owns server configuration, authentication, and execution. Agents find MCP tools with `tool_search` and call them by their `mcp__<server>__<tool>` names, and in Code Mode as `tools.<name>` inside `exec`. The native Figma tools are separate; they read Figma files, components, variables, and renders.
- `agent_browser` automates web pages through the optional `agent-browser` CLI.
- On macOS, the computer-use tools inspect and operate desktop applications through a native helper that needs the Accessibility and Screen Recording permissions. [Set up computer use](computer-use.md) covers installation, permissions, and configuration.
- Claude Code-compatible lifecycle hooks run from Pi settings. `/hooks` browses them, and `/add-dir` adds a working directory and runs the `DirectoryAdded` hooks.
- The [RPC host bridge](../rpc-host-bridge.md) lets Waku identify the installed choco-pi profile and read its durable background-work and goal entries. When `CHOCO_PI_HOST=waku` is set, RPC mode streams bridge progress; `/host-bridge` provides snapshots and background-work controls without starting a model turn. Pi's RPC UI carries user dialogs.

## Models and usage

- `/effort` sets the reasoning effort, and `/fast` sets the session's Fast mode preference. With Fast mode on, OpenAI models send the request in the priority service tier (not with an `openai` sign-in; see [Authentication](authentication.md)). On `xai/grok-4.7` (api.x.ai), choco-pi sends the Grok 4.7 Fast variant `grok-4.7-build-fast` and records its turns at twice the base price. Other Grok models leave the saved preference inactive, and `/fast status` says why. `modelThinkingLevels` in settings assigns a default thinking level to each model.
- choco-pi sets `PI_CACHE_RETENTION` to `long` by default, which requests one-hour prompt-cache retention from providers that support it. A value you set explicitly wins.
- `/usage` (alias `/quota`) shows provider usage and reset times for Claude, ChatGPT, Synthetic, and Grok; `/synthetic:quotas` shows Synthetic quotas. Grok shows its subscription credit window with an OAuth sign-in, and a status-only row with an API key. Providers without credentials are left out and named on one dim `Not signed in: …` line.

## Interface

- A fullscreen TUI with Nord themes, a status line, and a `/status` dialog with Status, Context, Usage, Preferences, and Statistics tabs.
- `/stats` opens the Statistics tab, which shows token usage and metered list-price cost computed from this installation's session logs (`<agent dir>/sessions`, plus the session directory set by `sessionDir` or `PI_CODING_AGENT_SESSION_DIR`), with fork and rewind copies counted once.
  - **Period and scope.** The period is the rolling last 24 hours, the last 3, 7, or 30 days, or all time (`r` cycles). The scope is all projects or this one (`p` toggles).
  - **Sections.** Below the header, ←/→ switches between five sections, as in Preferences. Each section is 25 rows tall (fewer in a short terminal), and a longer section scrolls.
    - **Summary**: totals, and a token chart per day (per hour for the last 24 hours) fitted to the section.
    - **By Model** and **By Feature**: as many top rows as fit. By Feature covers MCP servers, code mode, subagents, built-in tools, browser, web, and compaction.
    - **Context & Compaction**: context sizes, and compactions by method and trigger, and by provider.
    - **Throughput**: tok/s (generation speed: output tokens over the request time after the first token) and time to first token for each model, with a chart of the busiest models' tok/s per day.
  - **Details.** Ctrl+O expands every row with details and throughput by provider.
  - **Caching.** A scan of the logs, and every period and scope computed from it, is reused for five minutes; Ctrl+O and section changes never scan again.
  - **Older sessions.** This profile records time to first token for each response. For older sessions, both tok/s and time to first token are fitted from request duration against output and marked est.
- Mermaid diagrams render in the terminal. When a response draws a diagram with box-drawing or arrow characters, the next request carries a hidden reminder to use Mermaid instead.
- Fuzzy `@` file mentions, slash-command completion anywhere in the prompt, and inline images that respect terminal multiplexers.

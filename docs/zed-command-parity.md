# Zed command parity

This inventory records the command set that choco-pi exposes to Pi and the ACP adapter and classifies each command by whether it completes headlessly, using the criteria in the Classification section below.

The inventory covers repository-owned extension commands, project prompt templates, project and package skills, and adapter-owned builtins. User-global skills outside this repository are not choco-pi commands and are not counted. The custom MCP adapter's seven prompt commands and `/mcp-auth` were retired; Pi's built-in MCP now owns `/mcp`.

## Classification

- **Headless** means the operation completes through ACP messages or the translated `notify`, `select`, `confirm`, `input`, or `editor` primitives. A text rendering of the same command data remains headless even when the TUI uses a richer layout.
- **Fallback** means a useful operation or summary remains, but an interactive view or editor is omitted. The user receives the result, a manual URL, or an explicit Terminal Thread instruction.
- **TUI-only (intentional)** means the command requires a custom view or sensitive prompt that ACP deliberately does not render. The user receives an explicit rejection or Terminal Thread instruction instead of silent success.
- **Unverified** means the handler is registered in source but excluded from Pi's published command catalog. Zed therefore cannot dispatch it through the current adapter, even when the handler itself uses compatible UI primitives.

| Classification         |  Count |
| ---------------------- | -----: |
| Headless               |     54 |
| Fallback               |      7 |
| TUI-only (intentional) |      1 |
| Unverified             |     12 |
| **Total**              | **74** |

## Reproducing the inventory

The source enumeration used these commands from the repository root:

```sh
rg -n 'registerCommand\(' .pi/extensions .pi/packages
rg -n 'mode !== "tui"' .pi
find .pi/prompts -type f -name '*.md' -print
find .pi/skills .pi/packages/choco-pi-lsp/skills .pi/packages/choco-pi-mcp/skills \
  -type f -name SKILL.md -print
```

The LSP loader registers commands from `.pi/packages/choco-pi-lsp/registration-manifest.json`, so that manifest was enumerated separately. The adapter-owned list comes from `builtinAvailableCommands()` in `.pi/packages/choco-pi-acp/src/acp/agent.ts`. The live catalog was checked by starting Pi in RPC mode and sending `{"type":"get_commands","id":"inventory"}`. That response contained 67 Pi commands: 39 extension commands, 7 prompt templates, and 21 skills. Six of the skills came from user-global directories and are excluded here. The adapter then adds its 8 builtins.

The original static scan found 44 fixed extension commands. Pi published 32 of them, hid 12 through `.pi/extensions/command-filter.ts`, and added 7 MCP prompt commands from cached server metadata. The MCP cutover removed those 7 prompt commands and `/mcp-auth`, while retaining `/mcp` under Pi's built-in extension. The current counts above reflect those removals; the other scan results have not been regenerated.

## Review-assist has an extension layer and an adapter layer

The extension and the adapter make separate decisions, and both now permit `/review-assist` from Zed:

1. `.pi/extensions/review/index.ts` calls `presentHeadlessReview()` when `ctx.mode !== "tui"`. `.pi/extensions/review/headless.ts` resolves targets through ACP-compatible `select` and publishes the bounded changed-file locations, diffs, risk text, saved-review summaries, and limitations built by `core/headless-presentation.ts` through `notify`. Locations are one-based. Under the adapter's `CHOCO_PI_ACP_NATIVE_DIFF=1` marker, Zed renders the notification as Markdown, so `core/headless-markdown.ts` writes it as Markdown: headings and prose outside code, file names as code spans, other untrusted text escaped, and each file's changes as a unified diff in a ` ```diff ` fence longer than any backtick run inside it. Hidden sensitive files are named once under Limitations and never shown. The adapter keeps only the first 10,000 characters of a notification, so the review stays within 9,500: the summary, limitations, the whole file list, risks, and saved reviews come first, then as many whole per-file diffs as fit, in order. When some do not fit, a notice right after the summary gives how many files' diffs and how many characters of diff were left out (hidden sensitive files are not counted), the file list marks those files "diff not shown", and the notice points to `/review-assist` in a terminal thread or a narrower target. A failure whose detail comes from git or `gh` shows that detail in a code block. Print mode and other RPC clients keep the plain text, with per-file old and new text, byte for byte.
2. The ACP adapter does not intercept `/review-assist` or any review command name. It dispatches through the ordinary extension-command forwarding path, so the headless presenter answers the request. Unknown commands are still rejected by the separate unknown-command check. `/review` is now the reviewer prompt template and expands into an ordinary model turn.

Observed behavior through a real Pi process after the rename (the opt-in `PI_ACP_REAL_PI=1` suites, run with a scratch home and agent directory, an unreachable placeholder model, `--offline`, and the worktree's extensions, prompts, and skills): Pi publishes both `review` and `review-assist`; `/review-assist branch main HEAD`, run from a working tree whose `main..HEAD` diff has hundreds of lines containing words such as `token`, `secret`, or `login`, produced the `Review:` notification in Zed and settled the turn without model-turn events or additions to Pi's model context. A scratch repository whose branch diff and uncommitted changes contain those words and a changed `.env` file showed both the review and `/diff`, and neither sent the `.env` contents. The no-argument picker was observed only before the rename, when it produced one ACP selection request whose cancellation settled cleanly with `Review target selection was cancelled.`

Two limitations remain and are stated in the command's own output. Comment editing, approve/reject decisions, and pull-request submission are still TUI-only, which is why `/review-assist` is classified as Fallback rather than Headless. Review diffs reach Zed as fenced Markdown text rather than native ACP diff widgets, and a review longer than one message shows only the diffs that fit; the `/diff` presentation below shows that the structured diff surface works, and moving review output onto it is a recorded follow-up, not a regression.

Before this was fixed, the adapter's credential-prompt guard also inspected notifications, so such a review reached Zed as the terminal-authentication warning instead of the review. The guard now inspects only requests that collect a reply; see [Adapter UI translation boundary](#adapter-ui-translation-boundary).

## /diff in Zed

Zed cannot host the terminal diff pane: the adapter cancels `custom` UI. It can render ACP tool-call content of type `diff` (`path`, `oldText`, `newText`; `Diff` in `@agentclientprotocol/sdk` `schema/types.gen.d.ts`), which the adapter already emits for edit tools. ACP lets an agent send a `tool_call` session update with any id, so the adapter can show a diff for a user command without Pi running a tool.

1. The adapter starts every Pi child with `CHOCO_PI_ACP_NATIVE_DIFF=1` (`src/pi-rpc/process.ts`). Outside the TUI and only under that marker, `/diff` (`.pi/extensions/diff/native-diff.ts`) takes the file list, with each file's status and line counts, from the diff store, reads old text from the `HEAD` blob (or, for the session source, from the session's first checkpoint tree) through the store's pinned, deadline-bound, output-capped git runner, and reads new text with the store's symlink-safe file reader. It sends the result as one `notify` whose first line is `choco-pi-native-diff/v1`. When the session source lists nothing but the working tree has uncommitted changes, a second, one-line `notify` gives their number and says that `/diff source uncommitted` shows them. A git failure or a directory outside a repository is reported with git's message in a code block and the directory as a code span. Other RPC clients and print mode keep the inline list.
2. The adapter (`src/acp/native-diff.ts`, `emitNativeDiff` in `src/acp/session.ts`) decodes that message and emits one `tool_call` with status `completed`, kind `read`, a Markdown summary, and, for each file, a text item `File n of m: <name> — <status>, +a -d` followed by its `diff` item: Zed draws a `diff` item without its path. The summary lists the shown files in the same order with their status and line counts, then the files not shown with the reason. For a rename or copy the payload also carries the previous absolute path; the adapter judges sensitivity on both paths itself, withholds contents when a rename's or copy's source (or the change kind) is missing, and builds every name from the validated paths, using the extension's relative name only to shorten a path it is the end of. The adapter sanitises each name itself (control characters become visible pictures) and writes it as a code span that no backtick in it can close; reasons and the title are escaped, so no name or reason forms Markdown. A malformed payload becomes a one-line error and is never shown raw. The envelope only selects this rendering and grants no exemption: notifications are display-only, and the credential-prompt guard inspects none of them.

Limits, enforced by the extension and again by the adapter: at most 30 files and 1 MiB of old plus new text in total, text files only. Binary files, files over a cap, and files that would overflow the remaining budget are listed by name with the reason. Files named `.env`, `.env.*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `id_rsa*`, `id_ed25519*`, `*.keystore`, `auth.json`, `.npmrc`, or `.netrc`, or with `secret` or `credential` in the path, are never read and are listed by name only. Only the uncommitted and session sources are presented natively; `/diff` with another source (such as `/diff source branch`) sends the inline list as Markdown, with file, branch, and base names as code spans and the rest escaped. Its usage text and a failure to find the default base (git's message in a code block) are escaped the same way.

Nothing reaches the model: Pi does not store notifications as session entries, and the synthetic tool call exists only on the ACP side. A real Pi process run of `/diff` through the adapter emitted the tool call with two diffs, listed `.env` by name only, and left Pi's message list empty. Zed 1.27 drew the synthetic tool call's diffs without their paths, which is why each diff now follows a name line; that version of the card, the empty-session line, and the Markdown review have not yet been checked in the editor.

## Adapter UI translation boundary

`.pi/packages/choco-pi-acp/src/acp/session.ts` is the classification boundary for extension UI requests. `select`, `confirm`, `input`, and `editor` become ACP elicitation. `notify` becomes an `agent_message_chunk`. `setStatus`, `setWidget`, and `setTitle` become `session_info_update`. A request that collects a reply (`select`, `confirm`, `input`, `editor`, or an unknown method such as `custom`) whose method, title, message, or placeholder contains a credential word (`auth`, `authentication`, `authorization`, `credential`, `login`, `pass`, `passcode`, `passphrase`, `password`, `secret`, `token`, `api key`, or `private key`; case-insensitive, whole words) is cancelled with a Terminal Thread instruction and its content is not forwarded; that warning carries `_meta.piAcp.sensitiveUiRequest`, which extension text cannot add. Display-only methods are never inspected: they cannot ask for input, and their text is routinely code, file names, and diffs. Pi's own MCP sign-in asks for the redirect URL with an `input` that contains none of these words, so it reaches Zed as an elicitation, as it did before this change. Any other method, including `custom`, is cancelled with:

> Pi custom UI request is not supported; cancelling it. Open a Terminal Thread to use the interactive Pi UI.

Every translated request has a bounded timeout and exactly one settlement path. The command-parity matrix uses a fake Pi process to assert adapter-side translation. The real-Pi no-hang case is opt-in via `PI_ACP_REAL_PI=1`.

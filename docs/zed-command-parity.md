# Zed command parity

This inventory records the command set that choco-pi exposes to Pi and the ACP adapter and classifies each command by whether it completes headlessly, using the criteria in the Classification section below.

The inventory covers repository-owned extension commands, project prompt templates, project and package skills, adapter-owned builtins, and the MCP prompt commands present in the live Pi command catalog during the scan. User-global skills outside this repository are not choco-pi commands and are not counted. MCP prompt commands are environment-dependent, so their seven-row snapshot must be regenerated when MCP server metadata changes.

## Classification

- **Headless** means the operation completes through ACP messages or the translated `notify`, `select`, `confirm`, `input`, or `editor` primitives. A text rendering of the same command data remains headless even when the TUI uses a richer layout.
- **Fallback** means a useful operation or summary remains, but an interactive view or editor is omitted. The user receives the result, a manual URL, or an explicit Terminal Thread instruction.
- **TUI-only (intentional)** means the command requires a custom view or sensitive prompt that ACP deliberately does not render. The user receives an explicit rejection or Terminal Thread instruction instead of silent success.
- **Unverified** means the handler is registered in source but excluded from Pi's published command catalog. Zed therefore cannot dispatch it through the current adapter, even when the handler itself uses compatible UI primitives.

| ---------------------- | -----: |
| Headless               |     60 |
| Fallback               |      7 |
| TUI-only (intentional) |      2 |
| Unverified             |     12 |
| **Total**              | **81** |

## Reproducing the inventory

The source enumeration used these commands from the repository root:

```sh
rg -n 'registerCommand\(' .pi/extensions .pi/packages
rg -n 'mode !== "tui"' .pi
find .pi/prompts -type f -name '*.md' -print
find .pi/skills .pi/packages/choco-pi-lsp/skills .pi/packages/choco-pi-mcp/skills \
  -type f -name SKILL.md -print
```

The LSP loader registers commands from `.pi/packages/choco-pi-lsp/registration-manifest.json`, so that manifest was enumerated separately. The adapter-owned list comes from `builtinAvailableCommands()` in `.pi/packages/choco-pi-acp/src/acp/agent.ts`. The live catalog was checked by starting Pi in RPC mode and sending `{"type":"get_commands","id":"inventory"}`. That response contained 67 Pi commands: 39 extension commands, 7 prompt templates, and 21 skills. Six of the skills came from user-global directories and are excluded here. The adapter then adds its 8 builtins.

The static scan found 44 fixed extension commands. Pi published 32 of them, hid 12 through `.pi/extensions/command-filter.ts`, and added 7 current MCP prompt commands from cached server metadata. The remaining fixed rows are 7 prompt templates, 15 repository skills, and 8 adapter builtins.

## Review has an extension layer and an adapter layer

The extension and the adapter make separate decisions, and both now permit review from Zed:

1. `.pi/extensions/review/index.ts` calls `presentHeadlessReview()` when `ctx.mode !== "tui"`. `.pi/extensions/review/headless.ts` resolves targets through ACP-compatible `select` and publishes the bounded changed-file locations, diff units, risk text, saved-review summaries, and limitations built by `core/headless-presentation.ts` through `notify`. Locations are one-based and diff units are per file with old and new text.
2. The ACP adapter no longer intercepts `/review`. It dispatches through the ordinary extension-command forwarding path, so the headless presenter answers the request. Unknown commands are still rejected by the separate unknown-command check.

Observed behavior through a real Pi process: an explicit target such as `/review branch main HEAD` produces a `Review:` notification and settles the turn without emitting model-turn events or adding anything to Pi's model context, and the no-argument picker produces one ACP selection request whose cancellation settles cleanly with `Review target selection was cancelled.`

Two limitations remain and are stated in the command's own output. Comment editing, approve/reject decisions, and pull-request submission are still TUI-only, which is why `/review` is classified as Fallback rather than Headless. Review diffs currently reach Zed as text rather than native ACP diff widgets; rendering them through the structured diff surface is a recorded follow-up, not a regression.

One caveat is worth knowing when reading review output in Zed. The adapter's sensitive-notification filter inspects notification text, so a review whose diff happens to contain credential-like keywords can have its notification replaced by the terminal-authentication warning. The turn still settles cleanly; the review content is suppressed rather than lost or corrupted.

## Adapter UI translation boundary

`.pi/packages/choco-pi-acp/src/acp/session.ts` is the classification boundary for extension UI requests. `select`, `confirm`, `input`, and `editor` become ACP elicitation. `notify` becomes an `agent_message_chunk`. `setStatus`, `setWidget`, and `setTitle` become `session_info_update`. Sensitive authentication requests are cancelled with a Terminal Thread instruction. Any other method, including `custom`, is cancelled with:

> Pi custom UI request is not supported; cancelling it. Open a Terminal Thread to use the interactive Pi UI.

Every translated request has a bounded timeout and exactly one settlement path. The command-parity matrix uses a fake Pi process to assert adapter-side translation. The real-Pi no-hang case is opt-in via `PI_ACP_REAL_PI=1`.

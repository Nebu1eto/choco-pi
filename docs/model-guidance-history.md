Fable 5.2 and Mythos 5.2 guidance provenance (2026-11-10): the `anthropic/claude-fable-5-2,anthropic/claude-mythos-5-2` section was written after reading, in full, <https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2> (“Prompting Claude Fable 5.2”, which covers Mythos 5.2 as well). From the guide: the model follows instructions as written, so a rule must state its own scope; a limit works inside the rule, not in a separate line; with code presented as the user's the model stays within the existing structure and reports nearby problems, and the “This codebase is yours” sentence widens its changes and is not cancelled by a scope rule elsewhere, so the section says the user owns the code and omits that sentence; ordinary obstacles are worked through and deliberate blockers are left alone. Not from the guide, and not tested by Anthropic: the investigation boundary itself. It is split by request type at the repository owner's direction: one hop out for a change request, the causal chain as far as the answer needs for a diagnosis, plan, or investigation, where the owner regards the model's thoroughness as an asset to use in moderation. The same holds for the `pessimistic` persona line in `.pi/SYSTEM.md` and `.pi/extensions/lib/agent-preferences.ts`, now bounded to failures of the requested work. Effort routing is unchanged; Fable 5.2 and Mythos 5.2 stay at `high` by user decision, although the guide suggests `medium` for interactive coding. Intended check: compare Fable sessions before and after for tool calls on paths the request never named.

### Failures

- Sol `background-shell`: ended after starting the shell, promising to report later instead of waiting.
- Sol `delegate-readonly`: ended while the subagent was running; its final message did not contain the answer.
- Terra `background-shell`: ended after starting the shell, promising to report later instead of waiting.
- Terra `delegate-readonly`: answered without obtaining the subagent result and did not identify `src/cart.ts`.
- Opus `background-shell`: ended after starting the shell instead of waiting for completion.
- Opus `delegate-readonly`: ended while the subagent was running; its final message did not contain the answer.
- Fable 5.1 `background-shell`: ended after starting the shell, promising to report later instead of waiting.

Across these noninteractive `-p` runs, every model except Astra exhibited the behavior of ending a turn after starting a background shell or subagent and saying it would report when the work completed. This is a model behavior finding in `-p` mode, not a harness error. The Astra, Fable 5.1, and Kimi K3 delegate processes did not exit, but their stored final messages passed the task checks and were therefore judged as passes with `processTimedOut: true` retained in `result.json`.

### Provider prefix structure

Anthropic request 1 exposed the 38 tools listed in the Opus audit report above. Codex exposed the same ordered list plus a 39th tool, `synthetic_web_search`, as listed in the Sol audit report. All 10/10 task runs for each Anthropic model structurally rewrote the prefix by adding `synthetic_web_search` on request 2. Each Codex model rewrote 2/10 runs, both due to the `tool_search`/`synthetic_web_search` order swap on rows that touched MCP or discovery.

Task verdict specifications 3, 4, and 9 and the timeout-with-answer rule were corrected before this baseline was finalized. The corrections were applied uniformly to all 60 stored rows through readjudication before merging.

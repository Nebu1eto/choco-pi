# Vendored: choco-pi-computer-use

This directory is a **vendored, renamed fork** of the upstream open-source package **@injaneity/pi-computer-use**. It is not the original repository.

- Original source: <https://github.com/injaneity/pi-computer-use>
- Base commit: `de72583`
- Base version: `0.5.0`
- Forked on: 2026-08-22
- License: MIT (upstream `LICENSE` copied verbatim)

## What was taken

- `extensions/computer-use.ts`, the TypeScript extension entry.
- All 27 files under `src/`, including the macOS, Linux, and Windows dispatch backends and the shared `helper-path.mjs` module.
- `scripts/setup-helper.mjs`, retained at its original package-relative path for runtime macOS helper installation.
- All four `native/macos/*.swift` files; three are compiled into the helper on every install (2026-10-16).
- The arm64 and x64 loose helper binaries under `prebuilt/macos/` (about 1.1 MB total); removed from the tree on 2026-10-16 (see the last entry).
- The upstream MIT `LICENSE` verbatim.

## Divergences

### Package identity and loading

- Renamed `@injaneity/pi-computer-use` to `choco-pi-computer-use`, changed the version to `0.5.0-choco.0`, marked it private, and declared that it supersedes the upstream package.
- Pinned `pi.extensions` to `./extensions/computer-use.ts` instead of scanning the extension directory.
- Removed the npm `postinstall` script. Local harness packages are not installed by npm; helper setup remains runtime-driven.
- Removed the upstream `pi.image` field and all package metadata aimed at publishing the upstream project. Added only the package-local `typecheck` script.
- Kept `typebox` and `@earendil-works/*` as optional host-provided peer dependencies. There are no other third-party runtime dependencies, so this fork has no vendored `node_modules/`.
- Added `tsconfig.json` extending the harness root configuration; there is no build step and no `dist/`.

### Runtime helper installation

- Kept the package-relative runtime installer call. On macOS, `ensureComputerUseSetup` and tool execution reach the current platform's `ensureReady`; `ensureMacosReady` calls `MacosHelperClient.ensureInstalled`, which spawns `scripts/setup-helper.mjs --runtime` only when the resolved helper executable is absent.
- Removed the GitHub-release ZIP fallback from `scripts/setup-helper.mjs`, including release URL/tag constants, network fetches, timeout handling, archive extraction, SHA256SUMS parsing and verification, temporary release files, fallback warnings, and release-specific help text. The fork version would not name an upstream release, and the installer builds the helper from the committed Swift sources.
- Retained Developer ID/local/ad-hoc signing, LaunchServices registration, and source-hash tracking. As of 2026-10-16 the pre-signed app bundle path, the loose-binary wrapping, and the `--allow-build`/`PI_COMPUTER_USE_ALLOW_BUILD` gate are removed; the script always compiles the host architecture (see the last entry).
- Removed Windows and Linux setup/build branches, paths, Cargo invocation, prebuilt copying, and related help text from the setup script. The script now rejects non-macOS platforms explicitly.

### Platform support and removed trees

- Native helper installation is supported only on macOS in this fork.
- Kept `src/platform/{linux,windows}` because platform dispatch guards those small TypeScript backends, but removed `native/{linux,windows}` and their Rust crates and build scripts. Removed non-macOS prebuilts as well.
- Removed `.github/`, `demo/`, `notes/`, `assets/`, `docs/`, `package-lock.json`, the root upstream `.gitignore`, and upstream project-process/readme files. The fork supplies a concise package `README.md` and `AGENTS.md` that state macOS-only support.
- Removed `scripts/build-native.mjs`, every `scripts/check-*.mjs`, and the remaining development-only scripts and signing assets (`make-signing-cert.sh`, `pi-computer-use.entitlements`, `pi-cubench-agent.mjs`). The package retains only the runtime installer.

### Erasable TypeScript

Node strip-types must load every source file. Three constructors used parameter properties; all were desugared without changing behavior:

- `src/cdp.ts` `CdpTab`: `ws`, `targetId`, and `title` are explicit fields assigned in its private constructor.
- `src/runtime.ts` `StaleResourceStateError`: `resourceKey`, `expectedEpoch`, and `actualEpoch` are explicit readonly fields assigned in the constructor.
- `src/runtime.ts` `StateStore`: `limit` is an explicit private readonly field assigned in the constructor, preserving the default value `128`.

No enums, namespaces, decorators, or other constructor parameter properties remain.

### Anti-slop type hardening

- Hardened the vendored TypeScript and setup script to satisfy the harness anti-slop rules without suppressions. The changes are type-only and behavior-preserving: protocol-owned response types, recursive JSON/accessibility node types, named result types, and boundary predicates replace `unknown`, broad dictionaries, widening assertions, and inline representation checks.
- Preserved all 11 tool names and schemas. Conditional helper request fields are still added only when present; no request field, JSON encoding, command name, response interpretation, or ordering assumption changed.
- The macOS helper IPC path now gives daemon envelopes and command results explicit protocol types. The Linux and Windows backends received compile-time protocol types only and remain dispatch-guarded and unsupported by this fork.
- Permission handling only names the existing `checkPermissions` response and source fields. Accessibility and Screen Recording decisions, attribution handling, prompts, and failure gates are unchanged.
- Helper setup and discovery logic are unchanged. The setup script replaces two representation checks with equivalent primitive/API-presence checks; installation, hash/staleness checks, signing, and LaunchServices registration retain their existing control flow.

### Tests and documentation

- Replaced the upstream source-text `scripts/check-tool-schemas.mjs` check with `tests/load.test.ts`, which imports the extension and bridge under Node strip-types and pins all 11 tool names plus their parameter-property and required-field shapes.
- Made `stateId` optional for the read-only `search_ui`, `expand_ui`, and `inspect_ui` tools. On a fresh operation they now establish a semantic observation internally; this capture disables OCR and images and never delivers input. The `act_ui.stateId` schema is also optional so a missing state reaches its structured runtime refusal, but actions remain state-bound and never auto-observe.
- Defined observation staleness using the existing per-resource scheduler epoch: an action state is stale when its saved epoch differs from the resource's current epoch after a write. Missing and stale action states now throw `ObservationRefreshRequiredError`, whose JSON message and typed `requirement` include `code`, `operation`, `reason`, the requested `stateId` when available, exact `observe_ui` refresh arguments, and both epochs for stale states.
- Added a test-only platform-backend replacement hook so transition tests can exercise full bridge executors without installing or invoking native helpers.
- Added this provenance record, package working rules, and fork-specific README.

### Non-interference policy

The vendored base silently escalated to foreground delivery (app activation, window raise, HID events) for coordinate clicks, editable refs converted to coordinates, and keyboard input without a ref, and retried in foreground after a background `didnt` or a helper `foreground_required` error. This fork removes both paths in TypeScript:

- Foreground delivery requires a host-issued grant: `foreground_grant` (bundle ids, `"*"` allowed, default `[]`) in `pi-computer-use.json` / `.pi/computer-use.json`, or the comma-separated `PI_COMPUTER_USE_FOREGROUND_GRANT`. No tool parameter can set it. `foregroundGrantCovers` in `src/config.ts` is the only check.
- `PreparedAction.wantsForeground` (formerly `needsForeground`/`usesCurrentFocus`) records a capability need and never authorizes anything. Policy is `ax_only` when headless (or when `PI_COMPUTER_USE_DELIVERY_POLICY=ax_only`), otherwise `background`; `foreground` is sent only when `wantsForeground` and the grant covers the target bundle id, and then the request carries `foregroundGrant: true`. `helperActRequest` throws if asked for foreground without a grant. `canRetryInForeground` is deleted.
- Each action is sent to the helper once, with one narrow exception: if a grant covers the target, the policy was `background`, and the helper refused with `foreground_required` and `effectPossible: false` (proof that nothing was delivered), it is retried exactly once as `foreground` with `foregroundGrant: true`. The trace then records `escalatedToForeground: true`, `escalationReason: "foreground_required"`, `backgroundFirst: true`, and `backgroundAttempt`. A `didnt`, a refusal whose effect is possible or unknown, or a refusal without a grant is never retried. Otherwise a helper `foreground_required` error or result, or a background `didnt` for `typeText`/`keypress` or a foreground-wanting action, yields `execution.outcome: "didnt"` and `execution.refusal` (`code`, `target`, `action`, `capability`, `effectPossible`, `grantHint`, `reason`). A transaction stops at the first refusal and reports `stoppedAt`; `act_ui` then returns `details.status: "foreground_required"` without a successor observation.
- `PlatformDeliveryPolicy` no longer includes `"default"`. `PI_COMPUTER_USE_DELIVERY_POLICY`/`PI_COMPUTER_USE_EVENT_DELIVERY` values `foreground`/`hid` are ignored and reported in `details.config.notes`.
- Every `act`/`actBatch` request adds `requestId` (UUID per request), `session: { id, generation }` (per-process id; generation increments on session shutdown), `deadlineMs` (absolute Unix epoch milliseconds), optional `foregroundGrant: true`, and `focusResolution: "ax_focused_element"` for focus targets. `requestId` is the semantic request id that the native `cancel` command will target; it is separate from the transport envelope `id` (`req_N`) that `helper.ts` assigns per socket command. The macOS backend keeps the requested policy for focus targets. The Swift helper source enforces these fields from protocol 7 (next subsection); the committed prebuilt binaries still predate it.
- Helper `frontmostBefore`/`frontmostAfter` response fields pass through to the execution trace when present.
- `tests/foreground-policy.test.ts` pins this behavior with the fake platform backend.

### Protocol 7: cancellation and ownership

`native/macos/bridge.swift` and `src/platform/macos/helper.ts` move to helper protocol 7. The committed `prebuilt/macos/` binaries are not rebuilt by this change and still report protocol 6, so the TypeScript client restarts a protocol-6 daemon and then fails with a mismatch until the prebuilts are replaced.

- **Grant enforcement at the native boundary.** A request's policy is `ax_only`, `background` (also for an absent or legacy `"default"` policy), or `foreground`. Delivery is `hid` only for `policy: "foreground"` with `foregroundGrant: true`; everything else posts by pid. `foreground` without the grant is refused up front with `foreground_required`. App activation, window main/focus/raise (`focusTargetForPhysicalInput`), the activation inside `postEvent`, and the `focusWindow`/`restoreUserFocus` commands run only with the grant; `postEvent` refuses HID delivery when the executing request carries no grant. With `focusResolution: "ax_focused_element"` the helper resolves the target pid's `kAXFocusedUIElementAttribute` (never system focus), delivers by pid, and refuses with `foreground_required` when that element belongs to another pid.
- **`effectPossible`.** Error payloads of `act`/`actBatch` carry `error.effectPossible`: `false` only when the request had not yet posted an event or performed an AX mutation (press, value write, focus set, scroll action). Batch step errors carry it too. `HelperCommandError.effectPossible` exposes it.
- **Frontmost evidence.** `act` and `actBatch` results include `frontmostBefore`/`frontmostAfter` pids.
- **Request identity and cancellation.** `act`/`actBatch` register under their semantic `requestId`s (all batch action ids map to one request). `{cmd:"cancel", target:<requestId>}` answers `{acknowledged:true, state, stoppedAt?, effectPossible?}` with `state` `stopped`, `completed`, `not_found`, or `stopping` (a fourth state the plan did not name: the request was flagged but did not reach a checkpoint within 300 ms). Checkpoints run before each atomic delivery unit (mouse move, each click press, drag start, scroll event, key press, each Unicode text scalar, atomic text), before each AX mutation, before each `actBatch` step, and on each settle-poll iteration; never between the down and up halves of one press, and a started drag always completes. `deadlineMs` (absolute epoch ms) is checked at the same points. A stopped request fails with `{code:"cancelled", effectPossible}` and `result: {outcome:"partial"|"rejected_before_delivery", stoppedAt, reason:"cancelled"|"deadline"}` (batches add `steps`).
- **Ownership.** `claim {session:{id,generation}}` makes that session the owner; the owner lease lasts 30 s from its last request that carried its session. `act`, `actBatch`, `focusWindow`, `setWindowFrame`, `beginInputSuppression`, `endInputSuppression`, and `restoreUserFocus` from any other session, from an older generation of the owner id, or without a session while an owner is live fail with `owned_by_other_session` (`effectPossible:false`) before argument validation. With no live owner, the first gated request with a session becomes the owner. `release` clears ownership for the owner id; `shutdown` is unchanged. Read-only commands are not gated.
- **TypeScript transport.** `daemonCommand` sends `cancel` for the in-flight semantic `requestId` on a second connection when a command is aborted or times out, waits at most 500 ms, and attaches the ack as `cancel` (plus `effectPossible` and any late `response`) to `HelperAbortedError` (message still `Operation aborted.`) or `HelperTransportError`. The client learns the session from act requests and stamps it on owner-gated commands that lack one. `ensureMacosReady` claims ownership after `ensureProtocol` once a session is known (before the first act the helper admits the first act's session); a refused claim throws `owned_by_other_session`. `release()` (behind `releaseMacosOwnership`) forgets the learned session before sending, so a repeated shutdown sends nothing. It never installs, probes, or launches the helper: it sends `release` only when the socket path exists as a socket and the command completes within 500 ms, and returns `false` silently on ENOENT, ECONNREFUSED, or timeout.
- **Bridge mapping.** `act_ui` maps a helper `cancelled` error, or a non-aborted client timeout whose cancel was acknowledged, to `details.status: "cancelled"` with `details.execution` `{outcome:"partial"|"rejected_before_delivery", stoppedAt?, reason, effectPossible, cancel?}`, and `owned_by_other_session` to `details.status: "owned_by_other_session"` with `outcome:"rejected_before_delivery"`. A possibly effective interruption clears the observation so the next action needs `observe_ui`. Caller aborts still rethrow.
- **Tests.** `tests/helpers/fake-helper-daemon.ts` is a wire-level protocol-7 fake (Node `net`, no native access) with scripts `s1-ok` through `s7-ownership`; `tests/helper-transport.test.ts` drives the real client and bridge over it through `PI_CU_SOCKET_PATH`. The fake writes `act`/`actBatch` rows to its `--log` file when answered (with `response` and `answeredAt`), other rows on receipt, and `cancel` rows with their `ack`; its S2/S6 outlines include a focusable `custom-1` "Custom View" node, and S4 holds a `typeText` past the client timeout until cancelled.

## Tier-B findings (Run B1)

Fixes for the two product findings in `docs/computer-use-e2e-evidence.md` "Run B1". Supersedes the statements above that ungranted `ax_only` text roles without settable focus keep the pid-coordinate path, that S2 refuses every ungranted non-field click, that S6 refuses every ungranted non-setText action, and that a granted S6 custom-view click answers `worked`.

- **No-AX-action clicks are refused before delivery (native).** In `act`, a `click`/`press` whose element has no `AXPress`, is not handled by the text-role AX focus path, and is not confirmed or inconclusive web content now throws `foreground_required` ("target has no accessibility action; pointer delivery needs a host foreground grant") unless the request is a granted `foreground` request. The refusal runs before any checkpoint, `markEffect`, AX write, or event, so `effectPossible` is `false` unless earlier work in the same request (an `ax_only` text focus write that failed, or an earlier batch step) marked an effect. This applies to `background` and `ax_only`. A granted `foreground` request takes the HID path as before. Elements with `AXPress` still use AXPress, including its vendored pid fallback when AXPress fails. Text roles still use AX focus, and web descendants keep their prior behavior, including the `ax_only` pid pointer path.
- **Outcome of a pid click on an element without an AX action (native).** After such a click, `act` polls a bounded settle window (6 x 50 ms, with a checkpoint on each iteration) for a change in the element's value or selection, the app's focused window, the sheet count, the onscreen CG window ids, or the frontmost app. It reports `worked` if it sees one; otherwise it reports `didnt` with `evidence.observableChange: false`.
